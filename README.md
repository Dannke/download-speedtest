# Download speedtest

Консольный скрипт на Python: делает 10 последовательных запросов к адресу, каждый раз скачивает ответ целиком
и печатает среднее время запроса, общий объём, скорость скачивания и разброс по запросам.

## Требования

Python 3.8+. Внешних зависимостей нет, только стандартная библиотека.

## Запуск

```bash
python speedtest.py https://proof.ovh.net/files/10Mb.dat
```

Пример вывода:

```
# 1:    10.49 MB за  2.731 с
# 2:    10.49 MB за  1.503 с
...
#10:    10.49 MB за  1.092 с

Успешных запросов: 10 из 10

                  среднее  медиана      мин     макс  ст.откл
Время запроса, с    1.386    1.204    1.092    2.731    0.492
Скорость, MB/s      9.287    9.847    5.011   11.042    1.827

Среднее время запроса: 1.386 с
Всего скачано:         104.86 MB
Скорость скачивания:   8.82 MB/s (70.59 Mbit/s)
```

## Единицы

- Время: секунды (`с`).
- Объём: мегабайты, **1 MB = 1 000 000 байт** (десятичные, не MiB).
- Скорость: **MB/s** (мегабайт в секунду); в итоговой строке в скобках то же в **Mbit/s** (мегабит в секунду, ×8),
  как у провайдеров и speedtest-сервисов.

## Как считается

- **Одно соединение.** Все 10 запросов идут по одному keep-alive соединению, как у браузера. Если сервер его закрыл,
  следующий запрос откроет новое. Редиректы (до 5) выполняются, для другого хоста открывается своё соединение.
- **Первый запрос обычно самый медленный.** В нём DNS, установка соединения, TLS, разгон TCP и холодный кэш
  сервера. Он входит в статистику, как и остальные. На его вклад указывают колонка «макс» и разница между средним
  и медианой.
- **Время запроса:** полное, от отправки запроса до прочтения последнего байта тела ответа (`time.perf_counter`).
  Время редиректов внутри запроса входит, паузы перед повторами не входят.
- **Скорость скачивания** (итоговая строка): общий объём тел ответов / суммарное время скачивания тел, от получения
  заголовков до последнего байта. Ожидание ответа сервера в скорость не входит.
- **Таблица:** среднее, медиана, минимум, максимум и стандартное отклонение по 10 запросам. Строка «Скорость» —
  это скорость каждого запроса по отдельности, поэтому её «среднее» может немного отличаться от итоговой скорости
  (итоговая взвешена по объёму).
- Объём считается по фактически полученным байтам тела (без HTTP-заголовков). Запросы идут с
  `Accept-Encoding: identity` и `Cache-Control: no-cache`, то есть без сжатия и по возможности мимо кэшей.

## Ошибки и повторы

- **429 и 503:** до 3 повторов. Пауза берётся из `Retry-After` (секунды или дата, не больше 60 с), а если заголовка
  нет, растёт как 1, 2, 4 с.
- **Обрыв соединения:** обрыв посреди ответа или закрытие соединения сервером повторяются так же, до 3 раз.
  Обрыв определяется по `Content-Length`: если получено меньше байт, чем обещал сервер, запрос не засчитывается.
- **Без повторов:** отказ в подключении, таймаут 60 с и прочие HTTP-ошибки (4xx/5xx).
- Неудачный запрос печатается с причиной, скрипт переходит к следующему. Итог считается по успешным.

Код выхода: `0`, если все 10 запросов успешны, иначе `1`.

## Ограничения

- Прокси из `HTTP_PROXY`/`HTTPS_PROXY` не поддерживается.
- Если ответ без `Content-Length` и не chunked, обрыв неотличим от нормального конца ответа.

## Тест

```bash
python -m unittest test_speedtest
```

Тест поднимает локальный HTTP-сервер и проверяет:
- 10 запросов идут по одному соединению, весь объём посчитан;
- редирект выполняется;
- 429 повторяется с паузой из `Retry-After`;
- обрыв соединения повторяется, а затем засчитывается как ошибка;
- `Retry-After` в виде секунд и даты разбирается правильно.
